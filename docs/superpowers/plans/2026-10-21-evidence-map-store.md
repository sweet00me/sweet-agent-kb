# Evidence Map and Store

按用户要求在当前会话顺序实现，沿用 brainstorming/TDD/verification 工作流；不修改现有 Graph、RAG、UI，不运行真实云端分析。

## 设计与接口

- 复用 Catalog 固定清单、Scope 子集校验、Reader 完整解析正文及安全 SQLite 连接；日记排除和可信目录白名单贯穿保存、执行和溯源查询。
- `evidence_schema.py` 定义人物/事件、实验参数、通用事实模板、请求/响应、严格证据 Schema 和 `EvidenceExtractor` Protocol。来源/SHA/全局 Unicode 字符与行列位置由服务端绑定，原文引用必须逐字匹配。提取器可返回窗口内位置，或仅提供在窗口内唯一匹配的引用。
- `evidence_store.py` 使用独立 `evidence_store.sqlite3`：任务、文档、批次检查点、证据四张表。任务身份绑定固定范围、模板/提取器版本及窗口配置；事务同时保存批次和暂存证据。重复结构化证据跳过，原文及版本变化拒绝复用。来源可按任务、文档和证据 ID 查询。
- `evidence_map.py` 按授权文档顺序消费 Reader，窗口含上一批尾部重叠；支持失败恢复和取消。已保存窗口只核对，不重复调用提取器；全文读取和每个窗口处理都成功后，复查源/缓存、覆盖连续性，再将暂存证据提升为已验证。
- 任务执行使用独立非阻塞 flock，避免并行执行或两个恢复者互相覆盖。进程退出释放锁；下次执行将遗留 running 状态记为 interrupted，继续已有检查点。
- `deepseek_evidence.py` 是独立、延迟构建的适配器；必须同时显式授权并设置 `DOCUMENT_ANALYSIS_ALLOW_DEEPSEEK=1`，默认关闭。测试始终注入模拟提取器/模拟模型。完整性验证只保证引用和位置可核查，不宣称模型结论已经过语义审判。
- 不归档旧完整正文；历史证据保留原引用和 SHA，查询时报告与当前来源的版本关系。跨批次证据支持范围受配置的重叠窗口限制，不承诺无限跨度事实的召回。

## 顺序与测试

- [x] Schema/可注入接口：先失败测试，再实现三模板、引用定位与输入限制，运行离线测试。
- [x] Store：先失败测试，再实现专用 SQLite、任务/文档状态、事务检查点、幂等性、来源查询和恢复锁，运行离线测试。
- [x] Map：先失败测试，再实现重叠窗口、逐文档执行、版本检查、取消/恢复和成功门禁，运行离线测试。
- [x] DeepSeek 默认关闭适配器：使用模拟模型测试两道授权和截断保护，不进行真实请求。
- [x] 联合回归、独立只读复核及新增文件/用法/限制说明；不开发 Reduce、实体消歧或 LangGraph 子图。

## 完成证据

- 新增 41 项离线测试通过；联合既有功能共 195 项测试通过，17 组其他离线回归全部通过。
- 独立只读复核发现“后续文档处理时较早文档变化，任务仍成功”的问题；已增加源文件/缓存两种先红后绿用例，并在任务收尾重查所有已完成文档，失效受影响证据。
- 另补实际子进程 `os._exit(71)` 后恢复、携带已保存证据的恢复、末批提交后 Reader 失败与取消恢复，以及精确歧义引用错误码断言。
- 未创建正式 Storage 的证据库或目录快照库；测试数据均在临时目录。未调用真实 DeepSeek、Embedding，不修改向量库。
- 新增文件、调用接口、授权方式与限制详见 `docs/evidence-map-store.md`。
