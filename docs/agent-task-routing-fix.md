# 通用任务工具选择修复（2026-10-22）

> 后续修正：本报告的范围澄清规则曾过度阻挡普通 RAG；当前私人查询、范围继承和前端报告兼容行为见[私人查询与消息输入修复](chat-retrieval-input-fix.md)。

## 修复前的边界

- `app/agents/graph.py::diary_tool_request` 在模型选择工具之前，以 Diary、梦境和人数用语生成工具调用，默认绑定 Diary 目录及 `people_events`。这会令某些未给出范围的问题跳过模型澄清。未发现活动 Agent 路径存在以 LoRA 或 mIoU 为条件的工具选择分支。
- 系统提示词、RAG 重新判断提示词及答案展示存在梦境专用规则。答案相关性函数还将特定梦境问句改写成固定主题词。
- 原通用机制仍然存在：模型原生工具调用、按工具名审批、Execution Guard、独立云端授权、来源校验、SQLite Checkpoint、Tracing 与 SSE；RAG 草稿不受支持时最多重新判断一次。
- 没有工具调用、没有伪造引用标记的私人事实草稿，原先直接视为普通回答，可能发布编造内容或复用历史拒答。另一方面，RAG 无命中后真正的范围澄清也会被严格事实引用检查替换成固定拒答。

## 本次修改

1. 删除 `diary_tool_request` 及其模型前置分支。所有知识主题通过已有 Agent 模型选择原生工具，不按主题构造目录、工具或模板。
2. 统一提示规则：公开问答与能力说明直接回答；精确日期、局部事实或片段使用 RAG；限定集合的汇总、统计、极值、比较和事件整理申请集合分析。模板按所需证据结构选择：`people_events`、`research_parameters`、`general_facts`。
3. 要求搜索保留完整问题中的限定，集合分析保留 `question` 的完整内容与 `scope_query` 的目录、文件、修改日期、类型、排除条件；没有明确范围先澄清，不因主题猜目录或默认选择全部文档。集合范围继续由现有 Scope Resolver 和权限策略校验。
4. 在既有引用检查入口增加 `source_dependency` 分类。普通回答、用户提供的内容、真正的范围澄清分别记录为 `ordinary`、`provided`、`clarify_scope`，均为 `not_applicable / plain`，不冒充来源核验通过。需要尚未查询的私人资料时，拦截草稿并返回 `private_lookup_required`。
5. 复用已有 `citation_replan` 检查点，每个用户轮次最多重新判断一次工具或澄清范围。转入集合分析仍经过原审批和守卫；来自私人无工具草稿的重判保留 `source_review`，来自 RAG 的重判保留 `rag_attempt`。工具、来源版本及核验服务错误不伪装成知识库不存在资料。
6. RAG 草稿被拒绝后，仅允许独立分类为真正范围澄清的回复以普通消息发布，并保留拒绝原因。`ordinary` 或 `provided` 分类不能将不受支持的 RAG 事实草稿放行。来源核验的 SHA256、位置、精确引用及数值检查不变。
7. 删除梦境专用相关性改写及人数固定附言。提及次数、分组数和确认的独立对象数采用通用说明。极值问题选择现有已核验比较输出中的 Python 极值，不再展示前八项内部证据统计；没有语义核验凭据的单值比较明确显示极值无法确定，不升级结构校验结果。

未新增 Agent 节点、分析模块、数据库表；未修改 Map、Entity、Reduce、Evidence Verification 算法。未修改云端开关、审批策略、执行守卫或预算配置。敏感文件排除规则继续适用，包括全文、检索及历史证据。

## 实际离线结果

最终全量回归 **369/369 通过，78.033 秒**；禁止外部网络连接及 DNS。另运行原 Agent 行为评测，**E01–E08 全部通过**，涵盖审批、守卫、ToolMessage 对应、审批记录清理、Audit、Tracing、Metrics。9 个涉及的 Python 文件通过语法检查，`git diff --check` 通过。

新增 15 项测试由 4 项来源依赖测试和 11 项端到端测试组成。端到端使用实际 HTTP/SSE、Agent、工具、审批、守卫、解析缓存、临时 SQLite、分析工作流和发布逻辑；只替换聊天模型、检索向量、提取器和语义验证模型。不是新增主题关键词分支后的字符串测试。

| 场景 | 实际验证 |
| --- | --- |
| Diary 梦境跨文档汇总 | 原生工具选择 → 等待人工批准 → 两篇允许文档提取 → 带来源发布；未进入排除文件 |
| 非 Diary 人物事件 | Fieldwork 目录走同一 `people_events` 工具链，输出实际传感器事件 |
| 实验记录最高 mIoU | `research_parameters`，实际 Python 同组极值 0.76；审批前提取次数为零 |
| 多篇论文比较 | `general_facts`，只处理明确两份文件，分别输出稀疏与稠密检索方法和文档引用 |
| 指定日期精确检索 | 原样保留路径及日期问题，走 RAG 自动只读审批策略，当前片段核验通过，不调用全文提取 |
| 普通知识与用户提供数据 | 无工具，原回答发布，明确不属于来源核验通过 |
| 私人问题没有调用工具 | 拦截模拟 99.9% 编造草稿，重新选择集合工具，人工批准前不提取、SSE 不泄露草稿 |
| 缺少范围与重复拒答 | 真正澄清可发布；反复编造或复制拒答被拦截，重判最多一次，不默认全库 |
| RAG 空命中 | 不宣称全库没有资料；允许范围澄清，不自动读取全文 |
| 日期、目录和排除限制 | 通过现有 Scope Resolver 只处理一份指定月份修改的实验文件；未核验比较不发布极值 |
| 敏感文件请求 | 即便批准工具，也返回 `access_denied`，正文读取与提取次数为零 |

完整回归还覆盖原有 RAG 引用、审批拒绝、独立云端授权关闭、执行错误、断线恢复、请求重放、预算和来源版本变化等路径。

复核修复前后 4 个算法文件及正式 Evidence/Synthesis/Catalog/解析索引 SQLite、Chroma SQLite：**9 个文件大小、修改时间、SHA256 均不变**。没有运行真实分析任务或更改正式知识库。

## 限制与真实验收

- 本次全部为模拟模型与隔离文档验证，没有调用真实 DeepSeek、Embedding 或正式 Chroma。它证明通用路由契约与完整执行链可用，不代表真实模型已经通过任意主题的选择准确率验收；本次不自动触发真实验收。
- 为避免按主题关键词猜测是否依赖私人资料，普通回答现在复用现有检查模型进行一次来源依赖分类，产生额外模型调用；极少数失败后澄清路径也需要分类。调用继续计入原 Metrics 并检查上下文预算，失败关闭，不发布未经批准的草稿。这不是新增分析阶段，也不是事实真实性验证。
- 现有 Scope 日期筛选仍指**文件修改日期**。事件日期、发表日期与修改日期不能互换，提示词要求含义不清先澄清。普通 RAG 保留原查询及范围核验要求，未新增向量元数据日期过滤接口。
- 现有统计不单列每一类对象的可确认独立数量；身份不明、不可比单位、未完成核验或不充分输出仍明确不确定。极值来自已核验同组记录，不自动宣称跨不同条件的全局最优。
- 答案组织继续筛选已存、已核验输出并使用文本相关性，不增加同义词语义重组或新的归纳调用；复杂表述的相关性仍需真实场景验收。
- 没有重启生产进程。运行中的后端需按原部署方式重新加载代码后才会使用本次修改。
